# 햄스터 2대·비버 2대·박쥐 1대: 한국 예선 제어 코어

이 문서는 `robo_control/qualifier.py`의 실제 동작과 아직 연결하지 않은 부분을 설명한다. 기존 6대 경로 예제와 별도로, 한국 예선 Senior 초안의 **물체별 운반·최종 점수·조작 확인**을 검증하는 새 모듈이다. 실제 로봇이나 드론으로 명령을 전송하지 않는다.

## 1. 이번 구성

| ID | 이름 | 작업 | 조작 장치와 확인 신호 |
| --- | --- | --- | --- |
| H1 | 햄스터 1 | 샘플 디스크 운반 | 디스크 고정/해제 서보, 광센서 |
| H2 | 햄스터 2 | 샘플 디스크 운반 | 디스크 고정/해제 서보, 광센서 |
| B1 | 한가한 비버 | 실린더 운반, 의료키트 배출 | 집게 서보, 집게 물체 감지, 큐브 1개 배출 장치 |
| B2 | 바쁜 비버 | 실린더 운반, 의료키트 배출 | 집게 서보, 집게 물체 감지, 큐브 1개 배출 장치 |
| BAT | 박쥐 | 위치·물체 관측을 제공할 드론 | 영상/위치 관측 연결부는 후속 구현 |

지상로봇은 4대이며 박쥐를 지상 주행로봇 1대로 계산하지 않는다. 기본 예제에서 비버 각각 큐브 2개를 미리 적재한다. 실제로는 로봇과 적재물 전체가 480×280mm 출발구역 안에 들어가야 하며, 본체·집게·적재물·드론의 실측 치수가 없어 지금 설정만으로 배치 적합성을 확인할 수 없다.

사용자의 “햄스터 오른쪽, 비버 왼쪽” 배치를 초기 위치 참고로 담았지만, 작업 중 두 종류가 절대로 만나지 않는다고 가정하지 않는다. 각 작업의 목적지는 여러 위치에 퍼져 있어 비버끼리뿐 아니라 햄스터–비버, 햄스터–햄스터 쌍도 확인해야 한다.

## 2. 읽은 규칙과 적용 범위

기준은 공식 자료실의 [한국 예선 참가 요강 v2 초안 r5, 2026-08-12](https://robotics-2026.web.app/files/rulebook-kr-v2-draft.docx)의 제4.2·4.3·5·7.2장 및 Senior 배점표다. 물체 치수와 LAB 슬롯은 [국제 룰북](https://robotics-2026.web.app/files/intl-rulebook-en.pdf)의 8~12쪽을 참고한다. 본선 추가 미션과 본선 점수표는 이 모듈에 적용하지 않는다.

디스크 미션이 있는 구성이므로 현재 모듈은 **Senior 예선 초안**만 구현한다. Junior에는 샘플 운반이 없고 실린더 수와 배점도 다르므로, 참가 부문이 Junior이면 이 프로필을 그대로 사용하면 안 된다. 초안 점수는 최종 공고에 맞춰 다시 확인해야 한다.

| 물체 | 필드 수량 | 이번에 운반할 수량·목적지 | 최대 점수 |
| --- | --- | --- | --- |
| 샘플 디스크 | 3개, Ø56mm | LAB의 서로 다른 Ø60mm 표시 원 3곳에 1개씩 | 30 |
| 의료키트 큐브 | 4개, 25×25×20mm | 병원 H 2개, PCC-L 1개, PCC-R 1개 | 40 |
| 빨강 실린더 | 4개, Ø20×20mm | 그중 3개를 H | 30 |
| 노랑 실린더 | 4개, Ø20×20mm | 그중 3개를 두 PCC에 나누고 각 PCC 최소 1개 | 30 |
| 초록 실린더 | 4개, Ø20×20mm | 그중 3개를 RZ | 30 |
| 합계 | 19개 | 16개 운반, 실린더는 각 색 1개씩 남김 | 160 |

여기서 “색에 맞게” 운반하는 것은 실린더다. 읽은 규칙에는 디스크 색과 LAB 색을 맞추는 별도 조건이 없으며, 디스크는 세 표시 원에 각각 하나씩 넣는다. 물체 인식은 모양/종류와 실린더 색을 함께 알아야 한다. 로봇 식별용 마커 색을 생략할 수 있어도, 환자 실린더의 빨강·노랑·초록 분류까지 생략할 수는 없다.

중앙 H형 검정선은 예선에서 밟거나 통과해도 무방하다. 키트를 제외한 샘플·환자 실린더는 제공되는 고정 배치에서 시작해야 한다. 옮기지 않는 실린더를 경로 확보 때문에 이동할 수는 있지만, 다른 목적지에 잘못 넣어 혼색 판정을 만들면 안 된다.

## 3. 경기장 좌표는 아직 검증용 설정이다

`config/qualifier_senior.json`의 `layout_status`에 잠정 설정임을 명시했다. 한국 예선 B-1 전체 도면과 B-4 Senior 고정 배치가 확인되지 않아, 예제 좌표를 공식 한국 예선 경기장 도면이라고 주장하지 않는다. 웹 시뮬레이터 `lib/mission.ts`의 장면과 Python의 시작 위치·물체 ID·목적지·운반 목표를 일치시켰다.

모든 좌표 단위는 **mm**이며 경기장 **왼쪽 아래가 원점**, x는 오른쪽, y는 위 방향으로 증가한다. 웹은 같은 좌표계에 m를 쓰므로 Python 좌표는 웹 값의 1,000배다. 직사각형 목적지는 경계 테이프를 제외한 **안쪽 경계**를 나타낸다. 원형 LAB 목적지는 원 중심과 안쪽 반지름으로 나타낸다. 예제의 외곽 참고치, 목적지 좌표, 실린더 순서, 시작점, 로봇 크기를 실제 제공 맵과 측정값으로 교체해야 한다.

| 항목 | 공통 장면의 mm 좌표·크기 | 근거 상태 |
| --- | --- | --- |
| 필드 | 폭 1143, 높이 1181 | 국제 1필드 참고 규격 |
| 출발구역 | 왼쪽 아래 (663, 0), 480×280 | 국제 참고 도면·출발구역 규격 |
| H 내부 | (320, 1001), 503×180 | 국제 도면 참고 내부치 |
| PCC-L 내부 | (0, 1001), 300×180 | 국제 도면 참고 내부치 |
| PCC-R 내부 | (843, 1001), 300×180 | 국제 도면 참고 내부치 |
| RZ 내부 | (683, 20), 440×240 | 출발구역 안의 잠정 설정 |
| LAB 중심 3곳 | (380, 75), (480, 75), (580, 75) | Ø60 규격, 장착 좌표 잠정 |
| 비버 B1/B2 중심 | (900, 210), (900, 65) | 임시 본체 126×100으로 배치 |
| 햄스터 H1/H2 중심 | (1055, 210), (1055, 65) | 임시 본체 126×100으로 배치 |
| 박쥐 초기 중심 | (742, 140) | 기체 외곽 150×150 가정, 실측 필요 |

디스크 D1/D2/D3는 (80, 200), (150, 200), (220, 200)에 둔다. 실린더의 12개 위치와 색별 ID는 웹 `OFFICIAL_LAYOUT.groundPoints`의 순서를 따른다. 큐브 ID도 웹과 같은 C1~C4이며 C1/C2는 B1, C3/C4는 B2에 적재한다. `released: false`로 시작하는 바닥 물체는 아직 운반 후 분리·안착 확인이 되지 않았다는 모델 상태다.

Ø56 디스크를 Ø60 슬롯에 넣으면 기하상 중심 오차의 여유는 반지름 차이 2mm뿐이다. 경계 접촉을 제외하므로 이 코드의 이상적 평면 판정에서도 중심 오차가 정확히 2mm이면 점수가 없다. 광센서는 디스크가 붙어 있는지 확인하는 용도로 쓸 수 있지만, 그 신호 하나로 LAB 중심 정렬까지 확인하지는 못한다. 내려놓을 위치 확인에는 카메라/라인·정렬 센서 또는 검증된 기계 가이드가 추가로 필요하다.

## 4. 바로 실행

저장소 루트에서 Python 3.11 이상으로 실행한다. 새 모듈 자체는 표준 라이브러리만 사용한다.

```console
python -m robo_control.qualifier
python -m robo_control.qualifier --compact
python -m robo_control.qualifier --config config/qualifier_senior.json
python -m robo_control.qualifier --fail-signal optical_present
python -m unittest discover -s tests -p test_qualifier.py -v
```

소스 저장소에서 실행하면 수정 가능한 `config/qualifier_senior.json`을 먼저 읽는다. wheel 등으로 설치한 경우에는 패키지에 포함된 `robo_control/data/qualifier_senior.json`으로 자동 전환한다. 두 파일은 동일하게 유지하며 시험에서 바이트 단위 일치와 저장소 밖 패키지 실행을 검증한다. 사용자 설정은 어느 설치 방식에서도 `--config`로 지정할 수 있다.

기본 실행은 `mode: explicit_synthetic_feedback_demo`가 붙은 JSON을 출력한다. `device_io`는 항상 false다. 성공 예제는 16개 운반 작업을 순서대로 검증하고 최종 160점 스냅샷을 만든다. 이 점수는 **합성 피드백으로 정상 흐름을 통과한 코드 예제**이며 실제 로봇이 160점을 달성했다는 의미가 아니다.

시연에서는 각 상태의 합성 확인 간격이 0.1초다. 따라서 출력의 `elapsed_s`는 가상 상태 전이 시계이며 이동 거리, 모터 속도, 그립 실패, 가감속을 반영한 실제 경기 소요시간이 아니다. 실제 120초 완주 여부는 경로 제어와 측정된 동작 시간을 연결한 후 확인해야 한다.

`--fail-signal optical_present`로 디스크 감지 실패를 넣으면 해당 조작이 타임아웃되어 중단되고, 네 지상로봇에 대해 0 속도/서보 유지 의도를 출력한다. `gripper_present`, `gripper_clear`, `hopper_loaded`, `optical_clear` 등도 실패시킬 수 있다.

## 6. 작업 할당 방식

기본 JSON의 `task_plan`은 웹 장면과 같은 작업 계획이다. H1은 D1/D3, H2는 D2를 각각 LAB-1/3과 LAB-2로 옮긴다. B1은 C1/C2/R1/Y1/G1/R2, B2는 C3/C4/R3/Y3/G3/Y2/G2를 맡는다. 큐브는 H에 C1/C3, 왼쪽 PCC에 C2, 오른쪽 PCC에 C4를 넣고, 노랑은 왼쪽 Y1과 오른쪽 Y2/Y3의 **1:2 배분**이다. `configured_tasks`가 물체 ID 중복, 역할, 적재 소유자, 목표 안착과 최종 160점 배치 충족을 검증한다.

명시적 `task_plan`이 없는 사용자 설정에는 `allocate_tasks(pieces, zones)`를 쓸 수 있다. 이는 각 물체에 한 번만 작업을 만들고 디스크는 H1/H2, 실린더와 큐브는 B1/B2에 할당한다. 이 일반 할당기의 노랑 기본 배분은 2:1이며 역시 Senior 조건을 충족한다.

이미 적재한 큐브는 실제 적재된 비버에만 할당한다. 큐브를 바닥에서 집는 경로는 구현하지 않았으므로 적재 소유자가 없는 큐브 설정은 거부한다. 웹 공통 장면은 `task_plan`의 명시적 배치점을 사용한다. 일반 할당기를 사용할 때는 서로 다른 검증용 격자점에 물체를 배치하고, ID순으로 각 색 3개를 고르며, 미적재 물체의 담당자는 작업 수가 적은 로봇을 우선한다.

이것은 역할을 어기지 않는 결정적 기본 스케줄이다. 가장 가까운 물체 선택, 출발 대기 순서, 예약 경로, 전역 최적 시간 계산은 아직 연결하지 않았다. 시연은 물체 조작을 순차 실행하므로 네 대 병렬 주행의 완주 시간을 증명하지 않는다.

## 7. 햄스터와 실린더 비버의 조작 상태

순서는 다음과 같다.

1. `approach`: 물체 접근 완료 확인.
2. `align_pickup`: 집는 위치와 방향 정렬 확인.
3. `close_servo`: 햄스터 고정부 또는 비버 집게 닫힘 확인.
4. `confirm_grip`: 햄스터는 `optical_present`, 비버는 `gripper_present` 확인.
5. `retract`: 운반 자세로 집게/고정부 회수 확인.
6. `carry`: 목적지 접근 완료 확인.
7. `align_drop`: 내려놓을 위치 정렬 확인.
8. `release_servo`: 디스크 고정부 또는 집게 열림 확인.
9. `confirm_clear`: 광센서/집게 비움 + 물체 분리 + 안정된 최종 위치 확인.
10. `retreat`: 물체를 가리지 않는 퇴각 완료 확인.

각 상태는 자신이 요구하는 확인 신호를 받아야 다음으로 진행한다. 서보를 열라는 명령을 보냈거나 “열림” 신호만 받았다는 이유로 성공 처리하지 않는다. `confirm_clear`에서는 대상 물체 ID가 일치하고, 관측된 실제 좌표가 해당 목적지의 안쪽에 완전히 들어가는지도 다시 확인한다.

## 8. 큐브 배출 상태

비버 위에 큐브를 미리 넣었다고 가정한다. `confirm_load → carry → align_drop → release_servo → confirm_clear → retreat` 순서이며, 실린더 집게로 큐브를 바닥에서 집지 않는다.

`hopper_loaded`는 이번에 배출할 큐브가 공급 위치에 있다는 확인이다. `hopper_gate_open_one`은 **한 개만 내보내는 계량 동작 의도**다. 실제 장치에는 큐브 두 개가 한 번에 떨어지지 않도록 분리 구조와 서보 제어가 필요하다. `hopper_clear`는 배출 통로/이번 큐브가 걸리지 않았다는 확인을 뜻하며, 큐브 저장통 전체가 비었다는 뜻은 아니다. 배출 후 물체 ID·분리·목적지 안착도 별도로 확인한다.

서보 핀 번호, 각도, PWM, 열고 닫는 시간은 실제 제작물에 따라 결정해야 하므로 임의 숫자로 채우지 않았다. 현재 의미 단위 명령을 실제 장치에 매핑하는 드라이버는 후속 작업이다.

## 9. 센서 피드백 API

`Manipulator(task, piece, destination, allow_synthetic=False)`가 한 물체 작업을 관리한다. 기본값은 합성 피드백을 허용하지 않는다. 시연만 명시적으로 `allow_synthetic=True`로 생성한다. `tick(now_s, feedback)`는 상태를 한 단계씩 진행시키고 명령 의도를 반환한다.

`Feedback`에는 관측 시각, 관측 대상 상태 `phase`, 확인 신호 사전, 선택적으로 실제 물체 ID·좌표·방향, 합성 여부가 들어간다. 다음 조건을 검사한다.

- 시간이 유한하고 단조 증가해야 한다.
- 관측 시각이 해당 상태 진입 이후여야 한다.
- 미래 관측이나 기본 0.25초보다 오래된 관측은 상태 전이에 쓰지 않는다.
- 다른 상태용 신호를 다음 상태에서 재사용하지 않는다.
- 필수 확인 신호는 실제 Boolean `True`여야 한다.
- 합성 허용을 켜지 않은 상태에서 합성 신호를 받으면 fault로 정지한다.

이는 피드백 형식 검증이며 센서 진실성을 보증하는 보안 장치는 아니다. 실제 센서 어댑터는 장치 ID, 시간 동기화, 패킷 순서, 센서 유효성 등을 관리해야 한다. `device_io: false`를 해제하는 옵션은 제공하지 않는다.

## 10. 오류와 120초 종료

각 상태에서 기본 4초 동안 확인이 오지 않으면 `sensor_timeout:<상태>`로 정지한다. 그 뒤 정상 신호가 와도 자동 재시작하지 않는다. 120초가 되는 순간에는 새 센서 성공을 처리하기 전에 `match_timeout`으로 정지한다. 정지 의도는 모든 바퀴 속도 0과 서보 `hold`이며, 떨어뜨리라는 명령을 보내지 않는다.

실제 장치의 통신 단절 때도 멈추게 하려면 로봇 마이크로컨트롤러의 독립 watchdog과 타임스탬프 검증이 필요하다. 현재 모듈은 장치가 없는 코어이므로 명령 JSON을 생성할 뿐, 실제 모터 정지를 실행했다고 보고하지 않는다.

종료 스냅샷은 120초 또는 조기 종료 시점에 고정해야 한다. 경기 뒤 물체가 바뀌어도 점수를 덮어쓰면 안 된다. `score_senior`는 120초 이후로 기록된 스냅샷을 거부하므로, 호출자가 실제 종료 시점의 마지막 유효 관측을 저장해야 한다. 촬영용 고정 카메라 2대와 종료 후 최소 5초 맵 유지 조건도 박쥐가 대체하지 않는다.

## 11. 최종 점수 API와 판정

`score_senior(pieces, zones, elapsed_s=...)`는 **현재 물체 목록의 최종 상태**로 점수를 다시 계산한다. “이전 작업 성공 횟수”를 점수로 누적하지 않는다.

`Piece`에는 물체 고유 ID, 종류, 실린더 색, 중심좌표, 방향, 분리 여부, 붙잡은 로봇 ID가 있다. 종류에 따라 디스크 반지름 28mm, 실린더 반지름 10mm, 큐브 평면 25×25mm를 사용한다. 큐브는 평면 회전에 따른 외곽 범위도 고려한다. 물체의 높이·기울어짐·쌓임을 재현하는 3D 물리 모델은 아니다.

- 로봇에 붙어 있거나 분리 확인이 안 된 물체는 점수가 없다.
- 중심점만 들어갔다고 인정하지 않으며 물체 평면 외곽 전체가 안쪽에 있어야 한다.
- 경계에 닿으면 점수가 없다.
- 같은 물체 ID가 중복으로 들어오면 잘못된 스냅샷으로 거부한다.
- 서로 겹치는 목적지 두 곳에 동시에 속하는 물체는 모호한 설정으로 점수에서 제외한다.
- LAB 슬롯당 디스크는 최대 1개만 인정한다.
- 큐브는 H 최대 2개, 각 PCC 최대 1개만 인정한다.
- 실린더는 색별 최대 3개, 각 30점으로 제한한다.
- 잘못된 색 실린더가 완전히 들어간 목적지는 그 구역 실린더 점수가 0이 된다. 큐브 점수까지 없애지는 않는다.
- Senior 노랑 양쪽 배분을 충족하지 못하면 노랑 점수 전체가 0이다.

혼색 PCC의 노랑은 그 PCC 점수에는 포함하지 않는다. 두 PCC에 노랑이 각각 있는지라는 물리적 배분 조건은 별도로 확인한다. 이는 제4.3장의 “해당 구역” 무효와 배분 조건을 각각 적용한 해석이다. 예를 들어 PCC-L에 노랑 2개와 잘못 들어간 빨강 1개, PCC-R에 노랑 1개가 있으면 노랑은 PCC-R의 10점만 인정한다. 운영진 최종 해석이 달라지면 이 사례와 시험을 함께 수정해야 한다.

## 12. 충돌 검사와 후속 연결점

`ground_conflicts(poses, clearance_mm=10)`는 H1/H2/B1/B2 모든 쌍의 원형 외곽 간격을 검사한다. 입력 반지름에는 본체뿐 아니라 집게·적재물의 현재 돌출 길이도 포함해야 한다. BAT는 이 2D 지상 검사 대상이 아니다.

이 함수는 현재 자세의 겹침 검사다. 경로 중간의 교차, 멈추는 거리, 브레이크 지연, 물체를 든 상태의 폭 변화까지 해결한 경로 계획기는 아니다. 실제 병렬 주행을 연결할 때는 예상 시간별 위치 예약과 통로 우선권을 추가하고, 충돌 예정 시 이동 의도를 보류해야 한다. 역할별 좌우 선호 구역만으로 충돌 검사를 생략하면 안 된다.

현재 이동 명령은 목표좌표 또는 의미 단위 이동 의도를 담고 바퀴 속도는 모두 0이다. `approach`·`carry`의 목표를 경로 추종기에 전달하고, 실제 도착/정렬을 측정한 뒤 피드백으로 돌려주는 연결부가 필요하다. `retreat`는 `motion_intent: retreat_from_released_piece`, 놓인 물체의 기준점, 110mm 퇴각 거리를 제공한다. 퇴각 목표는 이동 어댑터가 **현재 로봇 위치·방향과 장애물**을 바탕으로 산출해야 하며, 도착 전까지 `retreat_reached`를 보내면 안 된다. 메카넘이면 `vx, vy, yaw`를 네 바퀴 속도로 변환하고, 차동 구동이면 별도의 경로 추종기가 필요하다. 이 조작 코어는 주행 방식에 의존하지 않는다.

박쥐는 추후 카메라 프레임과 시간·카메라 자세를 받아 경기장 평면 좌표로 변환하는 관측 어댑터에 연결한다. 비행 제어, 영상 수신, 기체 통신 규격은 구현하지 않았다. 고정 카메라 관측도 같은 형식의 로봇/물체 추적 결과로 연결할 수 있다.

## 13. 검증 범위

신규 회귀시험은 정상 160점, 초기 0점, 실린더 혼색, 노랑 2:1과 3:0, 색별 상한, LAB 중복 슬롯, 경계 접촉, 큐브 회전, 미분리 물체, 최종 상태 재계산, 역할별 할당, 모든 지상 로봇 쌍, 광센서/집게/적재 확인, 신호 누락, 오래된 신호, 가짜 해제 성공, 120초 종료, 합성 피드백 명시 허용, CLI JSON을 확인한다.

이 시험이 통과하면 규칙 판정과 상태 전이의 소프트웨어 예제가 동작한다는 뜻이다. 실제 색 인식 정확도, 디스크 2mm 정렬, 큐브 한 개씩 배출, 로봇 충돌 없는 주행, 드론 자율비행, 120초 실물 완주는 하드웨어/영상/실측 데이터 연결 후 따로 검증해야 한다.
