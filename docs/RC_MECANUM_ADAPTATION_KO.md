# RC카의 전후·좌우 이동 원리를 소형 로봇에 적용하는 설계

## 결론

쿠팡 상품 사진의 바퀴에는 접지면을 비스듬히 가로지르는 굵은 롤러가 보이고,
상품 설명도 전후·좌우·대각선 주행을 명시한다. 따라서 이 제품은 앞바퀴를
꺾는 일반 RC카보다 **4륜 메카넘형 구동**일 가능성이 높다. 다만 공개 페이지에는
제조사 회로도, 모터 수, 독립 PWM 채널 수, 엔코더, 배터리 정격이 없으므로
내부 전자구조까지 확정해서는 안 된다.

현재 `hamster_print_ready_v0.7.scad`는 좌우 구동륜 2개와 후방 캐스터를 쓰는
차동구동이다. 이 구조는 전진·후진·회전은 가능하지만 차체 방향을 유지한
좌우 이동은 불가능하다. RC카 전체를 이식하는 대신 **메카넘 휠 배열과 제어
원리만 가져와 기존 126×100mm 급 차체를 4모터 구조로 다시 설계**하는 안이
적합하다.

분석 대상: [쿠팡 상품 9483204917](https://www.coupang.com/vp/products/9483204917)

## 왜 옆으로 움직이는가

메카넘 휠의 둘레에는 회전축에 대해 약 45도로 기울어진 자유 롤러가 있다.
모터가 휠을 돌리면 바닥에 전달되는 힘이 전후 성분과 좌우 성분으로 나뉜다.
네 바퀴에서 원하지 않는 성분은 서로 상쇄하고 필요한 성분만 더하면 차체를
돌리지 않고 옆으로 이동할 수 있다.

위에서 내려다봤을 때 네 휠의 롤러 축이 차체 중심을 향하는 `X` 모양이 되도록
왼손형·오른손형 휠을 배치한다. REV Robotics의 공식 설명도 이 X 배열과
대각선 바퀴 쌍의 힘 합성을 사용한다.

바퀴 순서는 `FL=앞왼쪽`, `FR=앞오른쪽`, `RL=뒤왼쪽`, `RR=뒤오른쪽`이다.
아래 표는 한 가지 기준 배선의 예다. 실제 모터 장착 방향에 따라 부호 전체나
개별 부호를 바꿔야 한다.

| 차체 명령 | FL | FR | RL | RR | 결과 |
|---|---:|---:|---:|---:|---|
| 전진 | + | + | + | + | 좌우 힘 상쇄, 전진 힘 합산 |
| 후진 | − | − | − | − | 전진의 반대 |
| 좌이동 | − | + | + | − | 전후 힘 상쇄, 왼쪽 힘 합산 |
| 우이동 | + | − | − | + | 좌이동의 반대 |
| 반시계 회전 | − | + | − | + | 차체 중심 기준 반시계 토크 |
| 시계 회전 | + | − | + | − | 반시계의 반대 |

전진과 좌이동을 동시에 섞으면 대각선으로 간다. 이때 두 바퀴의 명령이 0에
가까워질 수도 있다. 네 명령 중 하나라도 허용 PWM을 넘으면 네 값을 같은
비율로 나눠 방향 비율을 보존해야 한다.

## 제어식

차체 기준 속도를 `vx=전진`, `vy=왼쪽`, `ω=반시계 회전`, 휠 반지름을 `r`,
차체 중심에서 휠까지의 전후·좌우 거리를 `Lx`, `Ly`라고 하면 한 가지 X 배열의
역기구학은 다음과 같다.

```text
wFL = (vx - vy - (Lx + Ly)ω) / r
wFR = (vx + vy + (Lx + Ly)ω) / r
wRL = (vx + vy - (Lx + Ly)ω) / r
wRR = (vx - vy + (Lx + Ly)ω) / r
```

이 식의 부호는 휠 handedness, 모터 앞뒤 장착, 엔코더 증가 방향에 따라 달라질
수 있다. 처음부터 부호를 믿지 말고 차체를 받침대에 올린 뒤 여섯 가지 기본
명령을 낮은 PWM으로 하나씩 검증한다. WPILib의 MecanumDriveKinematics도
동일하게 차체 속도와 네 휠 속도 사이의 변환을 제공한다.

## 현재 SCAD에서 바꿔야 할 기구부

SCAD 명목치로 계산한 운용 외형은 바퀴 미리보기의 돌출 범위를 포함해
약 `126×100×100mm`다. 실제 투영은 본체와 `%wheel_preview` 사이의 간격을
포함한 비볼록·분리 형상이지만, 시뮬레이터는 이를 모두 감싸는 보수적 8각형
볼록껍질을 쓴다. 현 설계의 구동축은 2개뿐이므로 다음 변경이 필요하다.

1. 앞왼쪽·앞오른쪽·뒤왼쪽·뒤오른쪽에 모터 장착부를 각각 만든다.
2. 후방 캐스터를 제거한다.
3. 좌우 handedness가 맞는 메카넘 휠 2개씩을 X 배열로 배치한다.
4. 네 휠의 접지 높이와 축 평행도를 같게 만든다. 한 바퀴가 뜨면 옆걸음이 크게
   틀어진다.
5. 배터리와 보드를 차체 중앙에 두어 네 바퀴 하중을 비슷하게 맞춘다.
6. 휠을 포함한 완성 외형이 출발구역의 3×2 배치를 유지하는지 다시 실측한다.

현재 외형 그대로라면 고정 방향 기준 중심 좌표를 `x=94, 240, 386mm`,
`y=971, 1111mm`로 두는 3×2 배치가 가능하다. 좌우 최소 물리 간격은 20mm,
앞뒤 간격은 40mm다. 다만 각 로봇을 제자리에서 자유롭게 회전시키는 반지름
81mm(Ø162mm) 회전 포락 보조원 6개는 480×280mm 출발구역에 들어가지 않는다. 따라서 출발구역에서는
방향을 고정하고 아랫줄부터 순차적으로 이탈시켜야 한다.

위 좌표는 시뮬레이터의 좌하단을 원점으로 하고 `+x=오른쪽`, `+y=위쪽`으로
둔 내부 좌표다. 공식 도면 좌표가 아니며, 공식 맵의 원점·방향이 공개되면
변환해야 한다. 경기장 숫자도 명목치이므로 최신 공지의 공차와 실물을 다시
확인한다.

## 권장 전자구성

- 로봇 1대당 ESP32 1개
- 엔코더가 달린 소형 DC 기어모터 4개
- 모터의 실제 스톨전류를 견디는 양방향 4채널 드라이버
- 좌·우 handed 메카넘 휠 각 2개
- IMU 1개
- 배터리, 로직용 안정화 전원, 퓨즈 또는 전류 제한
- 물리 전원 스위치와 소프트웨어 명령 타임아웃

라즈베리파이를 각 로봇에 넣을 필요는 없다. 중앙 서버가 카메라 영상에서
`x/y/yaw`를 계산하고 경로를 만들며, 각 ESP32는 네 휠 속도 PID와 통신
watchdog만 담당하는 구성이 가볍고 단순하다.

## 쿠팡 RC카를 직접 분해해 활용한다면

### 빠른 검증: 리모컨 버튼 에뮬레이션

차량과 순정 수신 보드를 그대로 두고, 리모컨의 전진·후진·좌·우 버튼 접점을
ESP32가 전기적으로 대신 누르는 방식이다. 공장 RF 페어링을 그대로 쓰므로
가장 빨리 움직일 수 있다. 단, 버튼형 조종은 속도가 ON/OFF일 가능성이 높아
1m급 경기장의 정밀 정지에는 불리하다.

리모컨 접점은 멀티미터로 공통접지인지 키 매트릭스인지 확인한 뒤 적절한
소자로 에뮬레이션한다. 갈바닉 절연이 필요하면 옵토커플러나 PhotoMOS를 쓰고,
일반 아날로그 스위치·MOSFET은 공통 기준전압과 허용 입력범위를 먼저 확인한다.
전압 측정 전에 ESP32 GPIO를 직접 연결하면 양쪽 회로가 손상될 수 있다. 6대는
리모컨도 6개를 각각 페어링하고 교차 조종이 없는지 시험한다.

### 정밀 제어: 전자부 전면 교체

차체·모터·휠만 사용하고 수신 보드를 ESP32와 모터 드라이버로 교체한다. 이
방식은 PWM, 엔코더 PID, watchdog을 직접 구현할 수 있어 대회용으로 더
적합하다. 먼저 배터리 전압, 모터 정격, 스톨전류, 모터가 정말 4개인지 측정해야
한다. 완구 RF 프로토콜 역공학은 일정 위험이 크므로 마지막 선택으로 둔다.

## 목표 중앙 제어 폐루프 — 향후 구현

현재 웹 시뮬레이터는 임시 고정 경로 재생이며, Python 버전도 카메라 관측부터
ESP32 출력까지의 실물 폐루프와 8각형 시간예약 계획을 아직 구현하지 않았다.
실물 단계의 목표 구조는 다음과 같다.

1. 상부 고정 카메라 또는 허용된 드론 영상에서 로봇별 마커를 검출한다.
2. 경기장 기준점으로 영상 좌표를 mm 좌표로 변환한다.
3. 서버가 각 로봇의 `x/y/yaw`, 측정시각, 신뢰도를 유지한다.
4. 다중 로봇 경로계획기가 서로의 시간 예약과 8각형 외곽선을 고려해 다음
   목표 속도를 계산한다.
5. 메카넘 역기구학으로 차체 속도를 네 휠 목표속도로 바꾼다.
6. ESP32가 엔코더 PID로 각 휠을 따라가고, 서버는 다음 영상에서 오차를 다시
   보정한다.
7. 유효 명령이나 위치 측정이 끊기면 로봇이 자체 정지한다. 타임아웃은 고정된
   숫자를 그대로 쓰지 않고 `타임아웃×최대속도+실측 제동거리 < 계획 안전여유`를
   만족하도록 1대 HIL에서 정한다. 초기 시험은 짧은 값에서 시작한다.

메카넘은 회전을 줄일 수 있지만 횡이동 때 롤러 미끄럼과 진동이 커서 바퀴
회전수만 적분한 위치는 쉽게 틀어진다. 따라서 외부 카메라 보정, IMU 방향 유지,
로봇별 전후·좌우 속도 보정표가 필요하다.

## 제작 전에 반드시 확인할 값

- 쿠팡 판매본의 실제 `L×W×H`, 무게
- 모터 개수와 바퀴별 독립 구동 여부
- 배터리 전압·용량·커넥터
- 각 모터 스톨전류
- 비례 속도제어인지 버튼 ON/OFF인지
- 엔코더 유무
- 6세트 동시 페어링과 교차 조종 여부
- 휠 외경, 축 지름, handedness

## 단계별 시험

1. 받침대 위에서 휠 부호 6가지 명령 확인
2. 바닥에서 전진·후진 500mm 반복 오차 측정
3. 좌우 300mm 반복 오차 측정
4. 대각선과 제자리 회전 후 원점 복귀 오차 측정
5. 카메라 폐루프로 1대 목표점 정지
6. 2대 교차 경로와 통신 끊김 안전정지
7. 6대 밀집 출발 순차 이탈
8. 실제 조명·배터리 저전압에서 2분 전체 리허설
