# 2026-09-06 · 박쥐 드론의 관측 이점을 활용하는 버전

이번 버전은 드론을 단순한 상공 애니메이션에서 **필요한 대상을 더 잘 볼 수 있는 위치를 찾는 관측자**로 바꿨습니다. 햄스터 H1 1대와 비버 B1/B2/H2 3대는 그대로입니다. H2는 태그 1번을 유지한 세 번째 비버(B3)입니다. 실제 드론·모터·카메라 스트림 연결은 재료 확보 후 진행합니다.

- [전체 코드](https://github.com/galaxygamja/Robo)
- [Python 관측 계획기와 입력 계약](ACTIVE_OBSERVER_KO.md)

## 1. 화면에서 바로 확인하기

첫 화면은 박쥐의 이동 관측 모드입니다. `임무 시작`을 누르면 청록색 카메라 시야와 드론 이동 경로, 관측 중인 로봇, 기준점, 로봇별 관측 출처를 볼 수 있습니다. 드론 없이 쓰는 모드와 기존 지상 5대 혼잡 시험도 유지했습니다. 5대 시험은 시작 공간 때문에 드론 없음 전용이며 박쥐를 선택하면 기본 4대로 초기화합니다.

오른쪽 `박쥐 · 관측 위치 계획`에서 다음을 확인합니다.

1. `같은 가림 조건으로 비교`의 드론 없음 → 중앙 정지 → 이동 관측을 각각 실행합니다. 버튼마다 동일한 초기 장면으로 돌아가 자동 시작합니다.
2. 이 비교는 H2의 기본 위치 입력을 일부러 끊고, H2의 **시작 위치 위에 고정된** 작은 가림막을 둡니다. 가림막은 로봇을 따라가지 않고 지상 주행 공간을 막지 않습니다.
3. 중앙 시점에서 가려진 태그를 이동 관측이 다른 각도에서 찾으면 해당 로봇의 관측 출처가 박쥐로 바뀌고 지상 임무가 재개됩니다.
4. `드론 입력 시험`에서 영상 끊김, 기준점 보정 실패, 80/200/450ms 지연을 넣을 수 있습니다. 드론 입력이 실패해도 기본 위치 입력이 유효하면 계속 사용하며, 필요한 로봇의 유효한 위치가 둘 다 없으면 지상팀은 대기합니다.
5. `연속 확인한 물체`에서 최근 3회 확인한 물체를 봅니다. `안전 시험실`의 결과 JSON에는 관측원, 모순 ID, 복구 시간, 시점/시야/보정 상태와 임무 재정렬 횟수가 함께 저장됩니다.

기본 위치 입력은 **고정 카메라 2대라는 뜻이 아닙니다.** 웹에서는 장치 독립적인 합성 좌표 입력입니다. 실제 위치 센서 방식은 별도로 확정해야 하며, 드론이 있다는 이유만으로 기본 위치 입력 하드웨어까지 구현된 것은 아닙니다.

## 2. 드론이 실제로 하는 계산

### 관측 위치와 높이 선택

0.5초마다 후보 위치 75개와 현재 시점을 평가합니다. 관측이 끊긴 로봇을 가장 중요하게 보고, 오래된 관측, 정렬/집기/배치 작업과 혼잡 상황도 우선순위에 반영합니다. 현재 보이지 않는 로봇의 실제 위치를 계획기에 알려주지 않고 마지막 선택된 측정 또는 알려진 출발 위치를 힌트로 씁니다. 누락 시간이 늘면 위치 불확실성도 커집니다.

각 후보에서 대상의 높이, 화각, 화면상 표식 크기와 3차원 가림을 검사합니다. 표식 중심만 보이는 경우를 성공 처리하지 않도록 중심 및 네 모서리 광선도 확인합니다. 이 다섯 샘플은 모든 픽셀의 가림 부재나 실제 AprilTag 검출 성공을 증명하지 않습니다. 기준 표식이 네 개 이상 보이고 가로·세로로 충분히 퍼져 있는 시점만 사용합니다.

예상 관측 가치에서 이동 거리·높이 변경 비용을 빼서 시점을 고릅니다. 작은 개선 때문에 좌우로 계속 왕복하지 않도록 변경 임계값을 둡니다. 이것은 제한된 후보 중의 휴리스틱이며, 경기 전체의 최적 경로나 최고 점수를 보장하는 학습 AI가 아닙니다.

### 좌표 입력 보완과 안전 대기

기본 입력과 드론 입력 중 신선하고 유효한 좌표를 로봇별 하나씩 선택합니다. 평균을 내거나 하나의 로봇을 두 대로 세지 않습니다. 선택된 촬영 시각을 과거로 되돌리지 않습니다. 웹에서는 300ms가 지난 관측과 1mm를 넘는 가상 오차 상한을 거부합니다. 같은 로봇의 두 관측이 오차 범위 및 시각 차이 동안 가능한 이동량을 넘어 모순되면 그 좌표를 선택하지 않고 전체 지상팀을 대기시킵니다.

지상팀이 위치 부족으로 멈춰도 박쥐는 유효한 관측 위치를 계속 찾을 수 있습니다. 단, 전체 입력 중단이나 비상정지에서는 드론도 모의 대기합니다. 비상정지와 경기 종료 이후에는 위치를 계속 바꾸지 않습니다. 이것은 소프트웨어 상태 정지 시험이지, 실제 공중 기체의 안전 착륙 절차가 아닙니다.

### 물체를 확인한 순서 활용

드론 시야 안의 합성 물체 관측을 3회 연속 확인합니다. 현재 예정한 원기둥의 새 관측이 없고 같은 비버가 맡은 다른 원기둥이 최근 확인되었다면 남은 원기둥 작업 순서를 바꿀 수 있습니다. 다른 비버의 작업을 빼앗거나 색별 목적지를 바꾸지 않습니다. 큐브와 햄스터 작업도 임의로 재배정하지 않습니다.

영상에서 물체를 봤다는 것만으로 집기·해제 성공이나 점수를 부여하지 않습니다. 기존 합성 센서 상태기계와 최종 배치 채점이 그대로 담당합니다. 웹 색은 장면의 정답 색을 사용하므로 실제 색 인식 정확도를 측정한 결과가 아닙니다. 이번 지정 가림 비교에서는 작업 재정렬이 필요하지 않아 횟수가 0일 수 있으며, 별도 시험에서 재정렬 기능을 검증합니다.

## 3. 같은 조건의 비교 결과

다음 결과는 **H2의 기본 관측 단절 + 시작 위치 위 고정 가림막**을 넣은 결정론적 가상 시험입니다.

| 관측 방식 | 위치 부족 대기 | 최종 점수 | 종료 | 충돌 검출 |
| --- | ---: | ---: | ---: | ---: |
| 드론 없음 | 119.98초 | 0점 | 120초 제한 | 0회 |
| 중앙 정지 드론 | 119.98초 | 0점 | 120초 제한 | 0회 |
| 이동 관측 드론 | 3.58초 | 160점 | 78.68초 | 0회 |

이동 관측에서는 드론이 누락된 H2를 보완한 시간이 75.10 로봇·초입니다. 위치가 처음 복구된 뒤 각 20ms 상태에서 지상 충돌과 12mm 이상 모형 여유도 검사합니다. 모든 기본 관측이 정상인 기존 4대 시험은 드론 없이도 78.66초/160점입니다. **따라서 드론이 항상 빠르다거나 드론 없이는 대회 수행이 불가능하다는 결론은 아닙니다.** 이 버전이 보여주는 이점은 특정 가림과 위치 입력 누락에서 운용을 복구할 수 있다는 것입니다. 실제 경기 시간이나 검출률은 실물 시험 전에는 모릅니다.

## 4. 모형 가정과 실제 구현 경계

웹 카메라는 아래를 보는 이상적 핀홀, 가로 90°·세로 78°, 1920×1080, 태그 40mm/높이 75mm, 10Hz·기본 지연 80ms를 가정합니다. 후보 고도는 0.65/0.8/1m, 수평 이동은 최대 0.28m/s, 수직은 0.4m/s입니다. 기준점 F1~F9와 150×150mm·높이 180~240mm의 공중 가림막은 **시험용 가상 설치물**입니다. 공식 경기장에 있다는 뜻도, 보내 준 장난감 드론의 사양이라는 뜻도 아닙니다.

웹의 매 프레임 보정 상태는 기준점의 기하학적 시야와 가정한 오차값으로 계산합니다. 실제 영상에서 동적 homography/PnP를 푸는 구현은 아닙니다. 로봇 자세와 색 검출도 합성입니다. 지상 경로 이동은 기존 이상적 기하 모델이며 웹이 실제 바퀴 폐루프와 연결된 것은 아닙니다.

실제 드론으로 연결하려면 다음 경계가 남아 있습니다.

- 카메라 내부 파라미터/렌즈 왜곡, 드론 roll·pitch·yaw와 흔들림, 노출/블러를 측정합니다.
- 실측한 경기장 기준점으로 **현재 프레임의** 카메라 위치·자세를 구해야 합니다. 고정 카메라용 보정값을 움직이는 카메라에 그대로 재사용하지 않습니다.
- 바닥과 높은 로봇 태그는 다른 평면입니다. 태그 높이와 장착 변환을 포함한 3D 변환이 필요합니다. 기존 비전 CLI의 `--moving-camera` 거부는 유지합니다.
- 각 관측원의 실제 촬영 시각을 공통 시간축에 맞추고 추적기로 전달하는 어댑터, 실제 비행 SDK/조종기 연결, 장치별 watchdog과 착륙·비상 절차는 아직 없습니다.
- LAB 디스크 중심 오차 2mm 미만은 합성 좌표가 아닌 전체 실물 오차 예산과 근접 정렬로 검증해야 합니다. Python 계획기의 완화된 15mm 입력 허용치는 정밀 배치 합격 기준이 아닙니다.

기술 근거: [OpenCV 평면 homography 설명](https://docs.opencv.org/4.x/d9/dab/tutorial_homography.html), [AprilTag의 태그 크기·카메라 파라미터 기반 자세 추정](https://github.com/AprilRobotics/apriltag#pose-estimation). 새 코드는 실제 비행 허용이나 대회 규정 적합성을 판단하지 않습니다.

## 5. 코드와 재현 명령

Python은 독립 라이브러리 모듈입니다. 웹과 서로 실시간 통신하지 않고, 기존 제어 루프에 자동 연결되지 않습니다. Python 데모의 카메라/장면/오차 기본값은 웹과 다르므로 수치를 직접 비교하면 안 됩니다.

```powershell
# 저장소 루트: 표준 라이브러리만으로 실행
py -m robo_control.active_observer --demo --compact
py -m unittest discover -s tests -v

# 웹 디렉터리: Node.js 22.13 이상
cd web_simulator
pnpm install
pnpm dev
node --experimental-strip-types tools/drone-comparison.ts --full
pnpm test
pnpm lint
pnpm build
```

- `web_simulator/lib/aerial.ts`: 가림/화각/기준점 모델, 시점 선택, 지연 큐, 좌표 출처 선택.
- `web_simulator/lib/mission.ts`: 관측 안전 게이트, 지상 임무 연결, 확인된 원기둥 순서 선택.
- `web_simulator/components/aerial-panel.tsx`: 관측 현황과 세 가지 동일 조건 비교.
- `web_simulator/tests/aerial.test.ts`: 이동 관측, 입력 실패, 만료, 모순, 시각 역행, 완주 회귀시험.
- `robo_control/active_observer.py`: 독립 3D 관측 계획기 및 여러 입력원의 좌표 선택 계약.
- `tests/test_active_observer.py`: 30개 관측 계획/입력 계약 시험. 5·6·12대 ID 목록도 검사하지만 그 대수의 실제 경기 완주를 보장하지 않습니다.
