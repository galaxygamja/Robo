## 선택 이유와 팀 작업 구분

팀원 영상 입력/태그/색/추적과 앞선 runtime은 실제 영상용 코드다. 웹 동선과
합성 센서/이동 데모는 시뮬레이션이다. 이번에는 이를 다시 구현하지 않고 기존 문서의
미구현 항목인 **렌즈 왜곡 보정**을 추가했다. 모터/보드/휠 사양을 가정하지 않았다.

## 이번 파일과 책임

- `vision/lens.py`: 해상도 고정 Brown5 파라미터, 원본↔이상 픽셀, 역변환/불안정 모델 검사,
  새 파일 저장, 설정 식별자. fisheye/고차 모델/자동 리사이즈는 지원하지 않는다.
- `vision/lens_calibrate.py`: 체커보드 사진 검출, 별도 검사용 사진을 남기는 렌즈 추정,
  사진별 RMS/최악 교차점/화면 범위/자세 다양성/입력 해시 보고서.
- `vision/lens_capture.py`: 명시한 USB 카메라에서 Space로 원본 PNG 수집, 주석/축소 저장 금지,
  중복 자세/나쁜 입력 거부, 원본/manifest 보존. 실제 장비로 GUI 시험하지는 않았다.
- `FieldCalibration`: 기존 schema 1 유지, schema 2에 lens 내장; 외부 좌표는 계속 원본 픽셀.
  중간 이미지 크롭 없이 원본→경기장 직접 역매핑으로 태그/HSV/주석 좌표 계약을 유지한다.
- `vision calibrate --lens`: 기존 네 모서리 선택 흐름에 렌즈 연결.
- `runtime`: 보정 schema 전체를 영상 프로세스에 복사; 검출 행에 렌즈 사용 여부/식별자 기록.
- `tools/verify_camera_runtime.py`: `--lens-fixture --colors-fixture`로 실제 영상 처리 통합 시험 확장.

### 시험 중 발견하여 수정한 문제

1. 최초 600초 렌즈+색상 시험은 **실패**했다. 태그/정지 감시는 동작했지만 색상 확인 횟수가 0이었다.
   실제 MJPG 디코딩 결과 빨간 중심의 HSV가 `[179,255,241]`였는데, 시험 설정은 H=0..10만
   포함했다. 경계 양쪽 H=0..10,170..179를 포함하도록 **시험용 설정**을 고쳤다.
   원래 마스크 윤곽의 원형도 0.476은 기준 0.5 미만이었고 수정 후 0.795였다.
   운영 HSV 검출기와 원형도 기준을 완화한 것이 아니다. 압축 영상→확인 상태 회귀를 추가했다.
2. 부하로 만료된 프레임을 정상 거부하면 측정 `robots`가 없는 로그가 나온다. 이전 검증 도구가
   이를 정상 측정처럼 읽다가 실패했다. 거부 입력은 측정값 비교 대신 **정지/사용 불가**를
   반드시 확인하도록 감사 도구를 수정하고, 비영점 출력이면 실패하는 회귀를 추가했다.
3. Windows 고장 주입 시험의 0.5초 기동 한계가 카메라 고장이 아니라 Python/OpenCV import
   부하에 걸렸다. 시험 프로세스 준비 완료를 먼저 기다린 뒤 고장 주입을 시작하도록 분리했다.
   실제 runtime의 기동 제한과 200ms/300ms/100ms 안전 제한은 바꾸지 않았다.

최초 실패 증거는 `recordings/lens-color-runtime-20260907-600s`에 보존한다.
