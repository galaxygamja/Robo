# Arduino 보드 코드 v2.0.0 배포 기록

2026-09-21. 대상은 사용자가 확인한 ESP32-C3 SuperMini, 햄스터1대 + 비버3대다.

## 수정 범위

- Arduino IDE에서 `arduino/RoboRobot/RoboRobot.ino`를 열어 빌드/업로드할 수 있는 완전한 스케치 폴더 추가.
- `setup()`/`loop()`와 실제 제어를 담당하는 C++ 파일·헤더를 함께 배포.
- H1의 기존 DC 모터 공통 출력을 SM-S4303R 연속회전 서보2개용으로 수정. 비버3대는 DRV8833/N20 구동 유지.
- 로봇 선택을 프로필1/2/3/4로 통일. B3의 기존 통신 ID H2는 유지.
- 구동 서보의 좌우 중립·정방향·펄스 한계, MG90S 작업 서보 범위를 설정할 수 있게 함.
- 물리 출력은 기본 비활성. 출력 허용과 보정 시험 확인 표시가 모두 있어야 활성화.
- 기존 통신 만료·재생 방지·비상정지 잠금을 유지하고, 응답에 실제 구동 프로필 정보를 추가.
- 큰 통신 버퍼를 정적 저장으로 옮겨 Arduino loop 스택 부담을 줄임.
- **Python 서버, 카메라 처리, 경로계획, 하드웨어 설정 schema1, 웹 시뮬레이터는 수정하지 않음.**

## 검증

- Arduino IDE와 같은 빌드 경로의 Arduino CLI로 `.ino` 프로필1/2/3/4 모두 컴파일 통과. 보드 `esp32:esp32:esp32c3`, 코어2.0.17, ArduinoJson6.21.5, USB CDC 활성/DIO 설정.
- 기존 PlatformIO 방식 H1/B1/B2/B3 네 환경 모두 컴파일 통과.
- C++ 구동 계산의 프로필4개 × 출력/보정 플래그4조합=16조합 컴파일 시점 검증 통과. -300..300 전 범위의 제한·반전·단조성·출력 차단을 constexpr로 검사. 별도 호스트용 실행 파일로 돌리는 네이티브 시험은 로컬에서 수행하지 않았고 CI에 등록했다.
- Python 전체 회귀시험863개 통과. 기존 서버/하드웨어 관련52개와 Arduino 스케치 동기화·안전 기본값 검사3개 포함. Python 서버 실행 코드는 변경하지 않았다.
- 기존 서버 파서에 새 응답을 넣은 네 로봇의 가짜 통신 hello/arm/명령/ACK 호환 검토 통과. 추가 필드를 포함해 응답 크기는 기존1024바이트 이내.
- 소스 ZIP에는 실제 비밀번호·토큰, 사용자 `Secrets.h`, 빌드 바이너리를 포함하지 않았다.

검증 결과 요약은 최종 패키지의 `BUILD_VERIFICATION.json`에도 들어 있다. **실제 보드 업로드·전압 측정·서보 중립/끝점 측정·실물 주행은 수행하지 않았다.**

## 사용자가 해야 하는 부분

Wi-Fi/토큰, 정확한 로봇 프로필, 실제 배선·전압, 서보 중립/회전 방향/끝점, 바닥 부하에서의 속도 곡선을 확인해야 한다. H1의 이전 DC 모터 보정값은 재사용하지 않는다.

기존 Python 서버는 새 펌웨어의 구동 방식 메타데이터를 자동 강제 확인하지 않는다. 사람이 실물 로봇과 업로드 프로필·부팅 로그를 대조해야 한다. 출력 해제는 물리적 제동/하중 유지/완전 정지 보증이 아니다.

처음부터 따라 할 절차는 [Arduino 시작 안내](ARDUINO_START_HERE_KO.md)에 있다. ZIP에서 `.ino`만 꺼내지 말고 폴더 전체를 보관한다.
