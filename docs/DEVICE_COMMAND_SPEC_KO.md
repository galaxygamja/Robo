# 장치·명령 규격 합의

> 소프트웨어 후속: [임무 모드의 차동 차체 속도](MISSION_ROUTE_RUNTIME_KO.md)를 구현했다.
> 방향 맞추기/전진/최종 방향 맞추기를 사용하며 휠/PWM은 미산출이다. 아래 ‘수정 전’
> 서술은 이 후속 이전의 기록이며, 기존 기본 메카넘 모드는 계속 보존한다.

2026-09-07 사용자 확인. 확정된 기구 방식, 잠정 가정, 미정 장치를 구분한다.
구조화 기록은 `config/device_spec.json`이다. 이 파일은 **합의 기록**이며 현재
runtime이 읽는 실행 설정이나 검증 완료된 통신 프로토콜이 아니다.

## 1. 확정 및 미정 사항

| 항목 | 현재 상태 |
|---|---|
| 대상 | 기존 지상 4대 H1/H2/B1/B2. 역할·태그 ID 유지 |
| 구동 방식 | **2륜 차동구동 확정**. 좌우 두 구동 바퀴의 차이로 회전 |
| 옆 이동 | 불가. 메카넘/옴니 구동을 실제 로봇에 사용하지 않음 |
| 엔코더 | 사용자가 없을 것으로 예상. **미장착 가능성이 높지만 최종 확정 아님** |
| 보드·모터·드라이버·전원 | 모델·핀맵·정격 미정. 과거 ESP32-S3/N20 제안을 확정품으로 취급하지 않음 |
| 바퀴 반지름·좌우 바퀴 간격 | 실측값 미정 |
| 집게·게이트·센서·물리 비상정지 | 실제 부품과 안전 동작 미정 |

‘회전이동’은 옆으로 미끄러지듯 이동하는 방식이 아니라 방향을 바꾸어 이동하는 뜻이다.
차동구동은 전진/후진과 회전을 결합한 곡선 이동도 가능하므로, 모든 이동에서
회전과 전진을 반드시 분리해야 한다고 확정한 것은 아니다. 첫 추종기는
**방향 맞추기 → 전진/후진 → 최종 방향 맞추기**로 단순화하는 안을 검토한다.
제자리 회전의 실제 가능 범위·간섭·모터 극성은 별도 실측한다.

## 2. 엔코더가 없는 경우의 제어 경계

- PC는 기존 카메라/AprilTag로 위치·방향을 다시 관측하며 목표 오차를 줄일 수 있다.
  엔코더가 없다고 모든 피드백 제어가 불가능한 것은 아니다.
- 보드는 엔코더 측정 없이 바퀴의 실제 회전 속도나 회전량을 안다고 보고하면 안 된다.
  **엔코더 기반 바퀴 속도 PID/바퀴 주행거리 측정은 사용하지 않는 안**으로 준비한다.
- 목표 속도와 실제 모터 출력의 관계는 실측해야 한다. 보정 전에는 PWM/전압을
  물리 속도(mm/s, rad/s)로 인증하거나, 명령한 이동량만큼 갔다고 적분해 성공 처리하지 않는다.
- 카메라 위치 폐루프와 모터 출력 제어는 구분한다. 카메라 가림 중에는 관측을
  추측해 계속 주행하지 않으며, 보드의 독립 명령 만료/정지와 물리 비상정지가 필요하다.
- 현재 200ms 관측 만료·300ms 검증용 명령 만료·100ms 감시 지연 기준은 바꾸지 않는다.
  이 호스트 소프트웨어 기준은 실물 제동 지연의 인증값이 아니다.

## 3. 명령 초안 — 아직 통신 형식 확정 전

상위 이동 의도는 차체 전방 속도 `v_mm_s`와 반시계 회전 속도 `omega_rad_s` 두 값으로
표현하는 안이다. 전방 속도는 양수가 전진, 음수가 후진이다. **옆 속도 명령은 없다.**
경기장 목표좌표는 서버의 경로 추종기가 처리하고, 차체 명령과 경기장 좌표를 섞지 않는다.

이 값은 목표값이며 측정 속도 보고가 아니다. 바퀴 간격, 모터/드라이버, 엔코더 유무가
정해지면 보드에 목표 속도를 보낼지 별도 보정된 모터 출력을 보낼지 최종 합의한다.
좌우 휠 순서와 극성, 출력 한계, 기동 최소 출력도 그때 정한다. 임의 상수를 넣지 않는다.

집기·열기·팔 회수·키트 1개 배출은 기존 `Manipulator`의 의미 단위 명령을 재사용한다.
명령 접수와 실제 센서 완료는 별개이며, 없는 센서는 `unknown`으로 취급한다.
센서가 없는데 시간만 지나면 집기 성공으로 진행하는 규격은 만들지 않는다.

세션/명령 번호/중복 조작 방지/만료/수신 확인/상태 보고/재연결 정지는 다음 합의 대상이다.
PC의 단조 시각을 다른 보드의 시각과 직접 비교하는 기존 mock 형식을 그대로 전송하지 않는다.

## 4. 기존 코드와 충돌하는 가정 및 다음 수정

현재 `ClosedLoopController`와 `MockActuatorBank`는 **4륜 메카넘 검증용 코드**다.
이 문서/JSON을 추가했다고 차동구동 코드로 바뀐 것이 아니며 실제 모터 출력은 계속 미연결이다.

1. 차동용 경로 추종기를 추가해 진행 방향과 목표 방향을 따로 처리한다.
   기존 세계좌표 `vx, vy`에서 `vy`만 지우거나 휠 배열만 4개에서 2개로 줄이지 않는다.
2. 측정 자세→차체 전진/회전 목표→좌우 구동 출력의 계약과 검증기를 분리한다.
3. 회전 중 차체·집게·적재물의 간섭을 포함해 외벽/다른 로봇과의 위험 검사를 유지한다.
4. 기존 경로계획기의 경유점과 예약 시간을 실제 차동 이동·회전 시간에 맞춰 연결한다.
5. 옆 목표·후방 목표·각도 경계·관측 유실·정지·재시작을 영상/가짜 장치로 검증한다.

웹의 메카넘 옆 이동·양보·가상 45.18초 동선은 **과거 모델의 결과**로 보존한다.
차동구동에 맞는 이동/회전 제약을 적용해 다시 계산하기 전에는 현 차체의 성능으로 사용하지 않는다.

이번 변경 범위는 확정 사항 기록과 기존 안내의 경고 추가다. 제어 알고리즘,
웹 시뮬레이션, 기존 명령 패킷, 장치 출력 경로는 아직 변경하지 않았다.
