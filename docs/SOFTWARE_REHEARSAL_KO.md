## 1. 측정 좌표를 사용하는 모의 주행 제어

새 `robo_control/control_loop.py`는 목표와 **측정 위치**의 차이를 매 프레임 계산한다. 세계 좌표 속도와 회전 속도를 제한하고 로봇 좌표로 바꾼 뒤 네 메카넘 휠의 모의 속도를 출력한다. 로봇 ID와 수는 registry에서 읽으며 코드에 네 대를 고정하지 않는다.

폐루프 데모의 흐름은 다음과 같다.

`합성 위치 관측 → PoseTracker → 목표 오차 제어 → 충돌 위험 검사 → MockActuatorBank → 이상적 위치 갱신 → 다음 관측`

모든 로봇 쌍의 예상 이동 영역과 제동 여유를 검사한다. 위치 누락·만료·잘못된 ID·역순 프레임·종료된 세션은 전체 대기 출력을 만든다. 명령 수신 객체는 별도 시계 검사로 발행 후 300ms에 명령을 만료시킨다. 비상정지는 새 정상 프레임이 들어와도 저절로 풀리지 않는다.

중요한 경계:

- 데이터 입력 계약은 `vision detect --track`의 원본 metadata가 포함된 전체 JSONL 행이다. 소켓 서버나 실시간 하드웨어 전송은 만들지 않았다.
- 데모의 4·5·12대 목표 수렴은 로봇 사이 간격 800mm인 넓은 합성 시험장 결과다. 경기장 혼잡 시험과 다르다.
- 이동 목표 허용치 3mm는 LAB 디스크 중심 오차 **2mm 미만** 판정에 사용할 수 없다. `at_goal`만으로 집기·배치 성공이나 득점을 인정하지 않는다.
- Python 객체의 watchdog은 펌웨어 watchdog이 아니다. 프로세스 전체가 멈추면 이 객체도 실행되지 않는다.
- `device_io`, `hardware_ready`, `motion_permitted`는 항상 false다. 장치 활성화 요청은 거부한다.

상세 계약·값·한계는 [모의 폐루프 설명](CONTROL_LOOP_KO.md)에 있다.

## 2. 색 물체 연속 추적

새 `robo_control/vision/object_tracking.py`를 `--track`에 연결했다. 기존 HSV 검출 결과인 `objects`는 그대로 보존하고, 그 위에 `object_tracks`를 추가한다.

1. 색·종류·위치 거리를 비교하여 일대일로 관측을 연결한다.
2. 기본 3회 연속 확인된 물체에 세션 ID `O0001` 등을 유지한다.
3. 같은 색 물체가 가까이 겹쳐 어느 것이 어느 것인지 모호하면 기존 ID를 임의로 교환하지 않는다. 같은 위치에 서로 다른 색 후보가 겹쳐도 중복 물체로 확정하지 않는다.
4. 누락 즉시 집기 유효 관측에서 제외하고 기본 500ms 뒤 만료시킨다. 완전히 잃은 물체가 다시 나타나면 물리적으로 같은 물체라고 단정하지 않는다.
5. `mark_gripped` / `mark_released`는 등록 로봇과 명시 근거가 필요한 별도 API다. 영상만 보고 실제 집기·해제를 성공 처리하지 않는다. 해제 위치도 새 영상에서 3회 확인되기 전에는 확정 관측이 아니다.
6. 녹화 속도 계산·만료에 미디어 시각을 사용하고, 프레임 신선도는 호스트 시각으로 검사한다. Windows의 같은 시각 눈금에 여러 프레임이 들어와도 순서가 증가하면 처리한다.
7. 종료된 추적 세션은 닫힌 상태를 유지한다. 거부된 프레임도 유효한 순서 정보는 소비하여 더 오래된 입력의 재사용을 막는다.

사용 예시는 카메라가 생긴 뒤 적용한다. 현재는 자동 생성 영상 시험으로 확인할 수 있다.

```powershell
.\.venv\Scripts\python.exe -m robo_control.vision detect --camera 0 --calibration recordings/camera.json --tags config/robot_tags.json --fleet config/qualifier_senior.json --track --colors config/object_colors.json --object-confirm-frames 3 --object-max-distance-mm 40 --object-miss-timeout-ms 500 --object-ambiguity-mm 5 --preview --report recordings/live-positions.jsonl
```

색 임계값·40mm 연결 거리·500ms 만료·5mm 모호성 기준은 시작값이지 실측 최적값이 아니다. ID는 같은 프로세스 세션 안에서만 의미가 있다. 가림 이후 동일성 증명, 다중 카메라 융합, 디스크·큐브의 미확정 색 프로필까지 구현했다고 해석하면 안 된다.

## 3. 시뮬레이터의 혼잡 회복

기존 5대 시험에서는 H2가 통로를 막고, 다른 비버는 회전하거나 구역을 사용하지 못한 채 기다렸다. 임무를 끝내고 주차한 로봇도 통로를 막았다.

이번에는 2초 이상 실제 진행이 없을 때 다음을 시도한다.

- 현재 방향을 유지한 옆 이동 후보를 검사한다.
- 차체·팔·적재물과 벽/물체/모든 로봇의 충돌을 확인한다.
- 회전 공간과 목표로 이어지는 경로가 있는 후보로 잠시 양보한 뒤 원래 작업을 재개한다.
- 완료된 비버가 길을 막으면 안전한 다른 주차 위치로 실제로 이동한다.
- 비싼 경로 탐색은 한 번에 최대 3개 후보로 제한한다.

순간 이동, 장애물 삭제, 안전 간격 축소, 가짜 완료/가짜 점수로 해결하지 않았다. 그래도 모든 배치의 교착을 해결하는 최적 스케줄러는 아니다. 후보가 없으면 안전 대기를 유지하고, 경기 시각은 120초까지 흐른다.

5대 시험은 별도 UI 선택으로 제공하며 `extra5`가 H2의 R2 작업 하나를 맡는다. 출발 위치가 가상 드론 주차 공간과 겹치므로 **5대 시험은 드론 없이만** 제공한다. 박쥐를 선택하면 기본 4대로 초기화한다. 기본 4대의 드론 있음/없음 선택은 유지했다.

## 4. 공개 화면에서 할 수 있는 안전 시험

| 조작 | 실제 구현된 영향 |
|---|---|
| 위치 입력 지연 0 / 100 / 400ms | 과거 측정 패킷을 큐에 넣어 늦게 전달. 300ms 초과 위치는 팀 대기 |
| 오차 상한 0 / 0.5 / 3mm | 측정 좌표에 재현 가능한 흔들림. 설정 상한이 1mm를 넘으면 정밀 작업 보류 |
| 전체 위치 단절 / 선택 태그 누락 | 오래된 위치로 정상 관측을 가장하지 않고 팀 대기 |
| 비상정지 잠금 | 초기화 전까지 이동·조작 재개 금지 |
| 4대 / 5대 선택 | 같은 규칙·물체를 사용한 기본/혼잡 시험 |
| 시험 결과 JSON | 설정·종료 시각·현재 점수·현재 간격·대기 원인·회복 횟수·최근 로그 저장 |
| 검출 JSONL | 로봇 mm 위치와 `object_tracks`의 ID·색·상태·소유자를 로컬에서 재생 |

오차 상한 1mm는 실제로 오차를 자동 측정했다는 뜻이 아니라 **시험용 입력 조건**이다. 센서 오차만으로 LAB 전체 오차 예산이 충족되는 것도 아니다. 지도 운반의 주행·조작은 이상적인 기하 모델이며, 오차가 바퀴 제어·미끄러짐·집기 오차로 전파되는 물리 시뮬레이션은 아니다. 측정 좌표 기반 속도 제어 시험은 위 Python 모듈에서 별도로 실행한다. 두 프로그램은 아직 실시간 통신으로 연결하지 않았다.

JSON 결과의 `current_clearance_mm`는 저장 순간의 간격이지 경기 전체 최소 간격이 아니다. 로그는 최근 80개 이벤트로 제한한다. 테스트 코드는 별도로 매 물리 단계의 간격과 충돌을 검사한다. JSONL 파일은 서버에 업로드하지 않는다.
