# Robo 예선 임무 시뮬레이터 — 박쥐 이동 관측과 가림 복구

최신: **드론 없음 정상 실행, 공통 작업·경로 최적화, 정상/간헐 누락/지속 가림의 세 모드 비교**를 제공합니다. 같은 알고리즘과 속도로 비교하며 별도 브라우저 Worker에서 실제 모의 결과를 계산합니다. 기존 안전 시험실과 JSONL 모니터는 유지합니다. 실물 연결은 재료 확보 뒤 진행합니다. [전체 변경 안내](../docs/COORDINATION_COMPARISON_FIX_KO.md)

기존 6대의 목적지 이동 시험과 다른, **집기·운반·해제·최종 배치 채점** 시뮬레이터입니다.
기본 화면에는 **햄스터 H1 1대, 비버 B1/B2/H2 3대**가 있습니다. H2는 태그 ID를 유지한 세 번째 비버(B3)입니다.
웹 첫 화면은 박쥐 BAT 이동 관측 모드이며, 드론 없이 기본 위치 입력으로 수행하는 선택도 유지합니다.
이전 6대 차동/메카넘 비교·수동 조작은 위쪽 `기존 구동 시험` 탭에 그대로 보존했습니다.

[실행 사이트](https://robo-six-arena-simulator.magic-shark-7297.chatgpt.site)는 로그인 없이 누구나 열 수 있습니다.

19개 물체 중 16개를 옮기며 원기둥 3개는 남습니다. 디스크에는 색별 목적지 규칙이 없습니다.
색 인식은 원기둥에 필요합니다. 시뮬레이터는 정답 색 정보를 사용하며 실제 영상 인식 AI는 아닙니다.
큐브만 사전 적재하여 B1·B2가 2개씩 갖고 출발합니다. 디스크/원기둥은 필드에서 집습니다.

현재 점수는 `scoreWorld(items)`가 **현재/종료 배치로 매번 새로 계산**합니다.
임무 완료 횟수나 이전에 들어갔던 기록으로 누적 점수를 주지 않습니다.

- 차체가 물체를 잡고 있거나, 완전히 분리·배치되지 않았으면 0점.
- 경계선에 닿으면 0점. 디스크 중심 오차는 2mm **미만**이어야 합니다.
- 디스크 두 개가 같은 LAB 원에 있더라도 해당 원은 한 개만 셉니다.
- 다른 색 원기둥이 들어간 구역은 그 구역의 원기둥 점수만 무효입니다. 큐브 점수는 유지합니다.
- 노랑이 한쪽 PCC에만 있으면 노랑 전체가 0점입니다.
- 혼색 PCC에도 실제 노랑이 있으면 양쪽 분배 조건에는 포함하되, 그 PCC 점수는 0점으로 합니다.
  ‘해당 구역 점수 무효’와 ‘각 PCC 최소 1개’를 별개로 읽은 초안 해석이며 주최측 판례를 확인한 것은 아닙니다.
- 웹 큐브는 축정렬 사각형으로 모의합니다. Python 판정기는 회전 각도를 반영합니다.
- 120초 도달 또는 조기 종료 선언으로 상태·점수를 고정합니다. 이후 자동 이동은 없습니다.
  최종 촬영을 위해 5초 이상 그대로 두면 됩니다. 출발 구역 복귀 점수나 보(beam) 배치는 없습니다.

## 팀 구성과 구현 방식

### 햄스터 H1

H1이 D1/D2/D3을 모두 담당합니다. 출발 구역 오른쪽에 놓지만 샘플이 있는 왼쪽 아래로 이동합니다.
따라서 햄스터-비버 충돌을 무시할 수 없습니다. 광센서는 **디스크 존재 확인용**이지 색/절대좌표 센서가 아닙니다.
원본 SCAD의 게이트는 바닥의 디스크를 가두는 구조로 해석했고, 임의의 리프트가 있다고 가정하지 않습니다.
화면의 전방 도달 거리와 수납 애니메이션은 조작 공간을 보는 단순화입니다. 원본 기구에 실제 신축 팔이 있다는 뜻이 아닙니다.

### 비버 B1/B2/H2(B3)

원기둥은 집게 서보로 잡고, 큐브는 별도 호퍼/배출 서보로 내보내는 가정입니다.
비버의 실측 CAD가 없으므로 현재 차체는 햄스터와 같은 126×100mm 명목 외형을 재사용했습니다.
집게 도달 거리 110mm(차체 중심 기준), 운반 시 72mm, 큐브의 전방 배출구는 설계용 가정입니다.
실제 집게의 폭, 호퍼 위치/높이, 큐브 낙하와 반동을 측정해 교체해야 합니다.

### 기본 관측: 실시간 좌표 추적

카메라 2대를 고정 가정하지 않습니다. 별도 10Hz 기본 위치 입력을 합성하고 측정 x/y mm·방향·나이·누락·관측 출처를 보여 줍니다. 드론 관측이 유효하면 기본 입력의 누락을 보완할 수 있습니다. 필요한 로봇의 모든 좌표가 300ms 넘게 오래되거나 누락되면 지상팀을 대기시킵니다. 0/100/400ms 기본 지연 큐와 0/0.5/3mm 좌표 흔들림을 선택하며, 오차 상한 1mm 초과 또는 관측원 간 위치 모순 시 주행을 보류합니다. 선택 시각은 과거로 되돌리지 않습니다.

좌표 지도 아래 JSONL 선택으로 실제 Python 검출 로그도 읽을 수 있습니다. 서버 업로드 없이 로컬에서만 재생합니다. 공개 화면에 실제 장비가 연결된 것은 아닙니다. 실제 로컬 좌표 모니터는 Python의 `--track --colors ... --preview`로 실행합니다.

공통 최적화의 기본 1햄스터·3비버는 이상적 모의 58.00초/160점, 최소 로봇 간격 약 12.200mm입니다. 5대 지정 혼잡 시험은 59.80초/160점·충돌 검출 0회입니다. `tools/fleet-expansion.ts`로 재현할 수 있으며 임의 배치나 대수의 완주를 보장하지 않습니다. 5대 시작 위치가 드론 주차 공간과 겹치므로 5대는 드론 없이만 제공하고, 박쥐 선택 시 기본 4대로 초기화합니다. 기존 78.66초는 공통 최적화를 끈 정상 4대 계획의 결과입니다.

웹 52개 회귀시험을 통과했습니다. 지도 주행은 여전히 이상적 기하 모델이고 관측 오차는 측정 좌표·안전 보류/감속에 반영됩니다. 바퀴에 대한 측정 좌표 폐루프는 저장소의 `robo_control/control_loop.py`에서 별도 모의 시험하며 이 웹과 실시간 연결하지 않았습니다. 마찰·미끄러짐·실제 제동·드론 비행은 미검증입니다. 비상정지는 초기화 전까지 유지합니다.

### 선택 관측: 박쥐 BAT

시작 구역에서 이륙한 뒤 누락된 로봇과 중요한 작업을 더 잘 보는 후보 시점을 고릅니다. 0.5초마다 75개 후보와 현재 위치를 평가하며, 표식 높이·화각·픽셀 크기·부분 가림과 분산된 기준점 4개 이상을 검사합니다. 지상팀이 위치 부족으로 대기해도 드론은 관측 복구를 위해 이동할 수 있습니다. 지상 운반은 맡지 않습니다.

가상 사양은 외곽 150×150mm, 후보 고도 0.65/0.8/1m, 수평 0.28m/s, 수직 0.4m/s, 10Hz, 1920×1080, 가로 90°/세로 78° 화각, 태그 40mm·높이 75mm입니다. 모두 연습용이며 기존 장난감 드론의 실측/SDK 성능이 아닙니다. F1~F9 기준점과 비교 시험용 공중 가림막도 공식 설치물이 아닙니다.

`실행 방식과 드론 활용`에서 정상 실행, 공통 최적화, 전략과 영상 끊김/보정 실패/80·200·450ms 지연을 바꿉니다. 기본 입력이 정상이면 드론 실패를 보완하고, 양쪽 모두 유효하지 않으면 대기합니다. 물체 연속 검출은 촬영 프레임 순번으로 계산하여 전달 지연과 분리합니다. 유효한 새 관측은 같은 비버의 남은 원기둥 작업 계획에 반영할 수 있지만 집기·해제 성공을 영상만으로 판정하지 않습니다. 색과 검출은 합성입니다.

`같은 조건 · 세 모드 비교`에서 정상/간헐 누락/지속 가림을 고릅니다. 정상은 세 모드 모두58초/160점입니다. 간헐 누락(8초부터H2입력10초마다1.2초 중단)은 없음65.82초/중앙58초/이동58초로 모두160점이며 추가 관측원의 보완 효과입니다. 지속 가림(H2입력 지속 중단+시작 위치 상공150×150mm 가림막)은 없음/중앙120초0점, 이동은3.58초 대기후60초160점입니다. 이것은 이동 관측의 복구 효과이며 정상 드론 없음에 고장을 자동 삽입하지 않습니다.

현재 보정은 합성 기준점 시야 검사이며 실제 동적 homography/PnP 구현이 아닙니다. 실제 드론·영상·조종기·무선통신은 연결하지 않습니다. 비행 허용 여부도 이 코드로 판단할 수 없습니다.

### 한 물체의 상태 변화

`접근 → 정렬 → 서보 고정 → 감지 확인 → 수납 → 집기 구역 이탈 → 운반 → 배치 정렬 → 해제 → 분리 확인 → 후퇴`

감지 확인 전에는 물체를 차체에 붙이지 않습니다. 운반 중 위치는 차체/집게를 따라 이동합니다.
큐브는 호퍼에서 배출구로 연속 이동하는 단순 애니메이션입니다. 목표에 갑자기 생기는 방식이 아닙니다.
분리 확인이 끝나야 물체가 필드에 남고 점수 계산의 대상이 됩니다.
서보 표시 0~100%는 정규화한 목표 상태이며 PWM 펄스나 실제 회전 각도가 아닙니다.
센서 감지/해제 응답은 타이머 기반 합성 신호이고, 선택한 로봇의 실패를 주입하면 1.5초에 오류 정지합니다.

## 경로와 충돌 계산

- 50Hz 고정 시간 스텝, 명목 0.22m/s 메카넘 이동 모델.
- 25mm 격자 8방향 A*, 막힌 경로 재계획, 모든 지상 차체·집게·운반 물체·남은 물체를 검사합니다.
- 평행이동 구간은 각 볼록 부품의 시작/끝 외곽을 합친 swept hull로 검사합니다.
  회전은 20ms 자세 샘플 검사이므로 완전한 연속 회전 충돌 해석이나 실물 안전 보장은 아닙니다.
- 126×100mm 바퀴 포함 보수적 메카넘 외곽, 전방 기구와 적재 물체 외곽, 최소 12mm 모형 여유.
- 좁은 격리/LAB는 한 번에 한 햄스터가 사용합니다. H/PCC/RZ 투하 구역도 상호 배타적으로 사용합니다.
- 집기 위치에서 바로 회전하지 않고 여유 공간으로 이동합니다. 두 비버는 서로 떨어진 회전 대기점을 씁니다.
- 완료한 로봇도 장애물입니다. 다음 로봇의 집기 위치에 주차하지 않도록 퇴각점을 따로 정했습니다.
- 공통 최적화는 같은 비버의 미시작 원기둥 순열 거리 비교, swept hull로 검증한 경로 직선화, 적재 후 짧은 회전 대기점 선택을 양 모드에 똑같이 적용합니다. 초기 연습 지도는 별도 불변 스냅샷입니다.
- H형 검정 테이프는 통과 가능한 선이지 물리적 벽이 아닙니다.

이는 제한된 작업 순서 탐색과 A*·경로 후처리의 조합입니다. 학습된 AI, 전역 최적 경로, 모든 임의 배치에서의 무교착을 보장하지 않습니다.
폐색 시 충돌을 강행하지 않고 기다립니다. 현재 장면은 고정색 연습 장면 하나이며 B-4가 나오면 재검증해야 합니다.

## 실행과 시험

Node.js 22.13 이상, pnpm:

```bash
pnpm install
pnpm dev
```

브라우저에서 `http://localhost:3000`을 엽니다. 웹 기본값은 `박쥐 이동 관측`입니다. 라이브러리 `createWorld()`의 인자 없는 기본값은 호환성을 위해 드론 없음으로 유지합니다.
`임무 시작`, 관측 방식, 속도, 로봇 선택, 센서 실패/관측 끊김,
조기 종료를 조작할 수 있습니다. 초기화하면 물체·점수·센서 상태가 모두 재설정됩니다.

```bash
pnpm test
pnpm lint
pnpm build
node --experimental-strip-types tools/drone-comparison.ts --scenario=normal
node --experimental-strip-types tools/drone-comparison.ts --scenario=intermittent
node --experimental-strip-types tools/drone-comparison.ts --scenario=occlusion
```

임무·관측·공통 계획·혼잡·기존 구동을 합쳐 총 52개 시험을 포함합니다.
정상 기본 장면은 58초의 **가상시간**에 16개 배치/160점으로 종료합니다.
각 20ms 상태의 외곽·물체 충돌, 물체 위치 연속성, 센서 실패, 관측 끊김, 경계선, 혼색,
LAB 정렬, 120초 종료와 최종 상태 고정을 검사합니다. 이것은 실제 대회 완주시간 예측이 아닙니다.

## 코드 위치

- `lib/mission.ts`: 장면, 역할, 물체 상태, A*, 기구 상태기계, 충돌, 점수, 종료
- `lib/aerial.ts`: 3D 가림·시점 계획·기준점·드론 프레임·로봇별 입력 선택
- `components/aerial-panel.tsx`: 드론 현황·장애 주입·세 가지 동일 조건 비교
- `tests/aerial.test.ts`, `tools/drone-comparison.ts`: 이동 관측 회귀시험과 재현 도구
- `lib/experiments.ts`, `lib/comparison-worker.ts`: 세 가지 동일 조건의 비교 계산
- `tests/coordination.test.ts`: 정상 실행/공정성/경로·작업 최적화/입력 누락 시험
- `components/mission-simulator.tsx`: 경기장, 물체/기구 애니메이션, 조작, 관측 모의
- `components/mission.css`: 반응형 화면
- `tests/mission.test.ts`: 임무 회귀시험
- `lib/simulation.ts`, `components/arena-simulator.tsx`: 보존한 6대 구동 비교 실험
- 저장소의 `robo_control/qualifier.py`: 같은 규칙/장면의 독립 Python 제어 코어
- 저장소의 `docs/QUALIFIER_CONTROL_KO.md`: 서보·센서·장치 어댑터 연결 단계

웹은 브라우저 안에서 실행되고 Python 코어와 실시간 통신하지 않습니다.
Python CLI 역시 합성 센서로 동작하는 별도 제어 시험입니다. 실물 연결 전에는 좌표 보정,
센서 피드백·타임스탬프, 통신 watchdog, 하드웨어 긴급정지, 기구 실측과 단계별 시험이 필요합니다.
